# SQLite через better-sqlite3, синхронный драйвер

Сервис один, процесс один, база один файл, поэтому берём better-sqlite3 с
синхронным API: транзакция «проверить, что слот свободен, и вставить запись»
выполняется атомарно без слоя ожидания, а инвариант единственной действующей
записи держит база, а не приложение. Асинхронный драйвер SQLite добавил бы
ожидание без выигрыша, а PostgreSQL требовал бы отдельного сервиса и доступа,
что для одного организатора и одного процесса избыточно.

## Consequences

- Операции с базой коротко блокируют event loop; это допустимо при объёме
  сервиса и должно учитываться, если нагрузка вырастет.
- Замена на другой движок возможна, но потребует пересмотра транзакции
  проверки и вставки: решение о синхронности зафиксировано осознанно.
